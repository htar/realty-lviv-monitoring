# Архітектура

## Потік даних

```text
Telegram-канали
  → teleproto: NewMessage / EditedMessage
  → перевірка активного username
  → parser + filter engine
  → SQLite: історія і дедуплікація
  → Telegram Bot API
  → приватний чат користувача
```

Паралельно бот виконує long polling `getUpdates`, приймає команди лише від `BOT_CHAT_ID`, змінює runtime-конфігурацію та записує її у SQLite.

## Компоненти

| Файл | Відповідальність |
|---|---|
| `src/index.ts` | MTProto-клієнт, події, запуск і graceful shutdown |
| `src/config.ts` | Zod-валідація `.env` і `config/search.json` |
| `src/parser.ts` | угода, об’єкт, місто, район, кімнати, ціна, посередник |
| `src/database.ts` | SQLite, дедуплікація, статистика і settings |
| `src/bot.ts` | Bot API, сповіщення і команди |
| `src/create-session.ts` | авторизація кодом |
| `src/create-session-qr.ts` | авторизація QR |
| `src/get-chat-id.ts` | визначення `BOT_CHAT_ID` |

## Обробка повідомлення

1. Listener отримує нове або відредаговане повідомлення.
2. Порожній текст і неактивні джерела пропускаються.
3. Парсер нормалізує український/російський текст і витягує поля.
4. Фільтр формує `matches` та причини відхилення.
5. Версія записується в SQLite.
6. Ключ `channel_id + message_id + content_hash` не дозволяє повторно обробити однакову версію.
7. Нова відповідна версія надсилається через Bot API й отримує `notified_at`.

Редагування тексту змінює SHA-256 `content_hash`, тому зберігається як нова версія.

## Парсер

Підтримуються:

- оренда: `оренда`, `здам`, `здається`, `сдам`, `сдается`, `довгостроково`;
- продаж розпізнається, але відсіюється;
- квартира/апартаменти, будинок/котедж, кімната;
- `1-кімнатна`, `2 кімн`, `1-комнатная` та словесні варіанти;
- `21 500 грн`, `18 тис грн`, `18000 UAH`, `₴`;
- Львів і Шевченківський район українською та російською;
- ознаки посередника: рієлтор, агентство, комісія, посередник.

USD/EUR визначаються, але не конвертуються й не проходять гривневий бюджет.

## SQLite

За замовчуванням: `data/realty.sqlite`, journal mode WAL.

`messages` зберігає IDs, hash, username, текст, посилання, дату, ознаку редагування, результат фільтра, JSON парсера та час сповіщення. Первинний ключ: `channel_id`, `message_id`, `content_hash`.

`settings` — key-value таблиця. Ключ `filters` зберігає JSON фільтрів, `channels` — JSON активних username. Ці значення перекривають `config/search.json`.

## Надійність і межі

- MTProto auto-reconnect і 10 connection retries;
- Bot API timeout 35 секунд;
- повтор long polling через 3 секунди після помилки;
- SIGINT/SIGTERM закривають Telegram і SQLite;
- дедуплікація повторної доставки.

MVP не має transactional outbox. Якщо процес завершиться між відправленням Bot API та `markNotified`, запис уже існуватиме й автоматичної повторної відправки не буде. Для production потрібна outbox-черга з retries.
