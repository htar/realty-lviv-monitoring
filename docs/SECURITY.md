# Безпека

## Секрети

- `BOT_TOKEN` — контроль над ботом;
- `TG_API_HASH` — секрет Telegram API application;
- `TG_SESSION` — довгострокова авторизована сесія;
- коди входу й пароль 2FA.

`TG_SESSION` не можна надсилати у чатах, issue, комітах або скриншотах.

## Зберігання

- Секрети лише в локальному `.env`.
- `.env` включено в `.gitignore`.
- `.env.example` містить порожні шаблони.
- На сервері обмежте права читання та використовуйте секрет-менеджер.
- Не вставляйте токени у URL, що залишаються в історії браузера.

## Компрометація

- `BOT_TOKEN`: відкличте в `@BotFather`, створіть новий, замініть у `.env`, перезапустіть.
- `TG_SESSION`: **Telegram → Налаштування → Пристрої**, завершіть сесію, створіть нову через `npm run session:qr`.
- `TG_API_HASH`: перевірте application на `my.telegram.org` і завершіть підозрілі Telegram-сесії.

## Контроль команд

Команди виконуються лише коли `String(msg.chat.id) === BOT_CHAT_ID`. Приховані `/channel*` команди не є окремим захистом — вони лише не показуються у `/help`; реальний контроль забезпечує `BOT_CHAT_ID`.

## Дані й логи

`data/realty.sqlite` містить тексти повідомлень, посилання й історію збігів; каталог `data/` виключено з Git. Логи можуть містити username та ID повідомлень, але код не повинен логувати токени або `TG_SESSION`.

## Допустиме використання

MTProto-акаунт слід використовувати лише для особистого моніторингу доступних джерел. Не використовуйте його для спаму, штучних переглядів, масового збору персональних даних або обходу правил Telegram.
