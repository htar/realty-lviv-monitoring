# Тестування

## Команди

```bash
npm run typecheck
npm test
npm run test:coverage
```

`test:coverage` примусово вимагає щонайменше:

- 98% line coverage;
- 90% branch coverage;
- 90% function coverage.

Поточний результат: 49 тестів, 98.07% lines, 93.52% branches, 98.21% functions для імпортованої бізнес-логіки.

## Покриті сценарії

### Parser і filters

- українські та російські оголошення;
- ціни з пробілами, суцільними цифрами та `тис/тыс`;
- оренда проти продажу;
- квартира, будинок, кімната та невідомий тип;
- одна/дві кімнати цифрами й словами;
- місто, основний і додатковий район;
- strict on/off;
- перевищення бюджету, відсутня ціна, USD;
- рієлтор/комісія;
- запити попиту `Шукаю`, `Шукаємо`, `Зніму`, `Ищу`, `Сниму`.

### SQLite

- створення схеми;
- збереження фільтрів і каналів;
- відсутні, пошкоджені та некоректно типізовані settings;
- дедуплікація однакової версії;
- нова версія після редагування;
- `markNotified` і статистика.

### Bot API і команди

- HTML escaping і формат повідомлення;
- fallback для відсутньої ціни/району;
- помилки Bot API;
- ігнорування стороннього `chat_id`;
- валідні й невалідні budget/rooms/district/strict;
- активні, порожні, додані, повторні й вимкнені канали;
- приховані команди;
- чиста зупинка polling після мережевої помилки.
- retry після тимчасової мережевої помилки;
- `/rescan`, невалідний діапазон, недоступний scanner і помилка MTProto;
- повторна доставка `matched=1` / `notified_at IS NULL`;
- ізоляція помилки одного каналу під час історичного сканування.

### Конфігурація і календар

- env defaults, coercion і помилки;
- Zod search config, deduplication username;
- некоректний JSON;
- календарні межі Kyiv у літньому/зимовому часі;
- переходи між місяцями й роками.

## CI

GitHub Actions запускає:

- typecheck і тести на Ubuntu, Windows і macOS;
- Node.js 22 та 24;
- coverage thresholds на Ubuntu/Node 24;
- Docker image build.

Workflow: `.github/workflows/ci.yml`.

## Що навмисно не запускається в CI

Живі інтеграції MTProto і Telegram Bot API не запускаються автоматично, тому що потребують `TG_SESSION`, `TG_API_HASH`, `BOT_TOKEN`, доступу до реальних каналів і можуть надсилати повідомлення. Це створило б нестабільні тести та зовнішні side effects.

Їх перевіряють контрольованими smoke-тестами:

```bash
npm run chat-id
npm run backfill -- --days 1
npm start
```

Для Bot API unit-тести використовують mock `fetch`; для історичного сканування перевіряються parser, SQLite і календарні межі, а реальний Telegram backfill запускається вручну.
